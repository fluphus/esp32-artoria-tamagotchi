# SaveManager 使用说明

通过串口与设备通信，按槽位（0/1/2）查询状态、导出 `.bin`、导入 `.bin`。脚本依赖 **Python 3** 与 **pyserial**：

```powershell
pip install pyserial
```

默认波特率 **115200**（与脚本内 `DEFAULT_BAUD` 一致）。

---

## 1. 运行方式

在 `SaveManager` 目录运行：

```powershell
py save_manager.py
```

不带参数进入**交互模式**：按提示输入串口号、波特率、超时（秒）后，可重复选择命令。

### 1.1 交互命令

| 简写 | 含义 |
|------|------|
| `st` | 查询存档槽状态，并对每个槽发送 `s0`/`s1`/`s2`，打印设备返回的状态块（或空槽提示） |
| `ex` | 导出**完整备份**（宠物 + 图鉴）到本地 `.bin`；默认建议文件名 `slot{N}_full.bin` |
| `ep` | 导出**仅宠物**（不含图鉴，用于串门/交换）；默认建议文件名 `slot{N}_pet.bin` |
| `im` | 将本地 `.bin` 导入到指定槽（设备根据文件内容区分完整恢复或串门，见下文） |
| `q` | 退出（也可输入 `quit` / `exit`） |

### 1.2 命令行模式

非交互使用时必须提供 `--port`，子命令为 `status` / `export` / `import`。

```powershell
py save_manager.py --port COM5 status
py save_manager.py --port COM5 export --slot 0 --out slot0_full.bin
py save_manager.py --port COM5 export --slot 0 --out slot0_pet.bin --pet-only
py save_manager.py --port COM5 import --slot 1 --in slot0_full.bin
```

可选参数：`--baud 115200`、`--timeout 10`（单次命令整体超时，秒）。

---

## 2. 导出：完整备份 vs 仅宠物

| 方式 | 交互 | 命令行 | 设备侧命令（脚本发送） |
|------|------|--------|------------------------|
| 完整备份 | `ex` | `export`（不加 `--pet-only`） | `SAVE_EXPORT <槽>` |
| 仅宠物 | `ep` | `export --pet-only` | `SAVE_EXPORT_PET <槽>` |

- **完整备份**：体积较大，含图鉴；用于整机备份与恢复。
- **仅宠物**：体积较小；用于与他人交换宠物、串门等场景。

导入时请使用与导出类型匹配的固件与流程；**导出与导入应尽量在同一固件版本下完成**。

---

## 3. 导入：文件类型与脚本提示

设备在 `SAVE_IMPORT_BEGIN` 后会输出 `[SaveImport] READY ...`，其中包含期望的载荷长度（含 `target_bytes=`，旧固件可能另有 `legacy=`）。脚本会校验本地文件字节数是否匹配，不匹配则**不会发送数据**，直接报错。

导入成功后，脚本根据设备输出行区分两类结果：

- **`[SaveImport] Full backup restored`**：完整备份已恢复到指定槽。
- **`[SaveImport] Visit started`**：串门流程——访客宠物已加载；**销毁（reset）访客宠物**会结束串门并恢复主人宠物。

若出现 **`[SaveImport] REJECTED`**，脚本会报错退出，请根据设备串口提示处理。

交互模式下选择 `im` 时，脚本也会简要提示：

- 带图鉴数据的文件 → 完整备份恢复（覆盖图鉴）。
- 仅宠物数据的文件 → 串门（冻结主人宠物，加载访客）。

---

## 4. 导入后的槽位规则（重要）

导入完成后，系统会把「导入槽」作为活跃槽之一；再从另外两个槽中选「更旧」的那个作为另一活跃槽，二者参与后续轮换存档；剩下一个槽冻结保留，不再参与后续存档覆盖。

> 「更旧」优先按 `sequence` 判断，必要时再用 `save_time` 判断；空/无效槽视为更旧。

（具体以当前固件逻辑为准。）

---

## 5. 导入后时间设置

导入完成后，设备通常会进入**设置当前时间**的流程，作为后续成长与离线结算的基准；该过程**不会**执行「从旧存档时间一路补算到现在」的离线结算。

若仅通过串口观察脚本输出，请关注设备屏幕或串口后续日志以完成设时。

---

## 6. 常见问题

- **串口无法打开**：请先关闭 `pio device monitor`、其他串口调试助手或任何占用该 COM 口的程序。
- **导入超时或卡在分包**：确认未被其他软件占用串口；导出与导入使用**同一固件版本**；尽量使用**新导出**的 `.bin`。
- **提示文件长度与设备期望不符**：说明备份格式或固件期望大小已变化，请用当前固件重新导出后再导入，或升级/对齐脚本与固件。
- **缺少 pyserial**：执行 `pip install pyserial` 后重试。
