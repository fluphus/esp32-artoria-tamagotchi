# 👑 アルトリア・たまごっち (Fate/Grand Order バーチャルペット)

このリポジトリは元の**アルトリアのゲームとv9セーブ形式**を維持します。ArtoriaとPocket Sproutを含む再利用可能なC++17エンジンは、別リポジトリ[embedded-tamagotchi-engine](https://github.com/fluphus/embedded-tamagotchi-engine)にあります。

**ESP32-S3 (N16R8)** を搭載した、たまごっち風のバーチャルペットプロジェクトです。

あなただけのアルトリアを育てましょう！セイバー・リリィから旅を始め、彼女の成長を導きます。お世話やコミュニケーションに応じて、アーチャー、ランサー、ライダーなど、様々なクラスへと進化します。

## ✨ 機能
* **進化システム：** ペットのステータス（健康度、真面目さなど）に基づく複数の成長ルート。
* **時間・日付管理：** 日替わりのリセットや、食事を与えなかった場合のペナルティを処理する内部時計を内蔵。
* **永続ストレージ：** 3スロットセーブ。チェックサム検証、シリアルでのフル／ペットのみエクスポート、フル復元またはビジット（ペットのみインポート）モード、デバイス紐づけの rounds／クロック状態、インポート時の拒否・整合処理に対応。
* **インタラクティブなアクション：** 餌やり、つつく（ポーク）、ステータス監視。
* **演出・表示：** 餌やり・コンボ・つつき・進化などの画面演出はアニメーションキューで順番に再生。待機の立ち絵は体力・真面目さなどの状態に応じて段階切り替え（**ロンギミニアド**／ランサー・アルトリア系の特例を含む）。Adafruit GFX / Adafruit SSD1351 経由の SSD1351 128×128 65K カラー OLED と、ヘッドレス検証用のシリアル・プレースホルダー。`assets/` 配下の PNG をフラッシュ内蔵のバイナリ資源に焼き込むことも可能（未配備時は自動でプレースホルダへフォールバック）。

## 🚧 現在のプロジェクト状況

* **ゲームプレイ・システム：** メインのゲーム機能（ループ、餌やりとコンボ、スペシャルフード、つつく、進化、日次締め、セーブのインポート／エクスポート、図鑑、破棄確認など）は一通り実装済みで遊べる状態。最近の更新で、餌やり・コンボ・つつきなどのカットシーンを「再生順を決め、決めた時間でコマ送りする」形に整理。待機のポーズはペットの状態から自動で選ばれ、フラッシュ上の画像を読み込む（未用意ならプレースホルダのまま）。
* **美術・素材：** 本番用のフレームアニメ／立ち絵は未確定または未接続の部分があります。現状デバイス上では**棒人間**に矩形とテキストを合わせたプレースホルダで、フローとレイアウトを検証しています。`assets/` のパイプラインで組み込み資源を生成すれば、同じロジックで実際の PNG シーケンスを表示できます。
* **ディスプレイ：** SSD1351バックエンド（Adafruitライブラリ）とシリアル版の両方をビルド済みです。この旧版修復ブランチの物理画面とボタンは実機未検証です。
* **入力：** 3 ボタン物理入力（L/M/R）、シリアル模擬に対応（`btn l|m|r`、`btnl l|m|r`、`btnr l|m|r`）。

## ビルド

```bash
pio run -e esp32-s3-devkitc-1            # SSD1351ビルド
pio run -e original-serial               # シリアル版ビルド
pio run -e esp32-s3-devkitc-1 -t upload  # 選択した環境を書き込み
pio device monitor -b 115200            # シリアルモニター
```

`assets/` 以下の PNG から組み込み資源を再生成するには、**Pillow** の入った Python 環境で `python tools/convert_assets.py` を実行してください（命名とディレクトリ規則は `assets/README.md`）。PlatformIO のプリビルド・フックは既定でコメントアウトしており、同梱 Python に Pillow が無い場合のビルド失敗を避けます。資源を生成していなくても、固件は棒人間／プレースホルダ表示でフローは動きます。

ビルド時に`original-serial`を選択してください。ヘッダーの変更は不要です。このバックエンドもESP32-S3上で動作し、ホストテストは別の周辺機器アダプターを使用します。PNG変換には`Pillow`、セーブツールには`pyserial`が必要です。

## スモークテスト手順（シリアル / ボタン）

シリアルコマンドを使用してボタン押下をシミュレートします。115200ボーで接続してください。

### 1. 起動から待機へ（Boot → Idle）
電源を入れて約1.5秒待ちます。初回起動／電源断後はボタンまたはSET_TIMEで日時を確認し、成功後に待機へ進みます。復旧ロック中は通常プレイできません。

### 2. ステータスパネル（Status Panel）
```
btn m          # ステータスパネルを開く
btn m          # ステータスパネルを閉じる（待機に戻る）
```

### 3. 餌やりフロー（Feed Flow）
```
btn l          # 餌やりドロー開始（4枚の食物カードをアニメーション表示）
                # ドロー完了まで約800ms待機
                # 自動的に餌選択画面に進む
btn l          # カーソル左移動
btn r          # カーソル右移動
btn m          # カーソル位置の食物を選択（3つ選択するまで繰り返す）
btn r          # 別の食べ物に移動
btn m          # 2番目の選択
btn r          # 3つ目の食べ物に移動
btn m          # 3番目の選択 -> 自動送信、餌やり結果を表示
                # 餌やり結果は最低1.5秒表示
                # その後自動的に待機に戻る
```

### 4. ノンコンボの餌やり結果ホールド（Non-combo Feed Result Hold）
3 つのエサを選んだあと（コンボなし）：
- PAGE_FEED_RESULTは最低1500ms表示
- この保持期間中は入力がブロック
- 保持期間終了後、ページは自動的に待機へ戻る

### 5. コンボ結果からスペシャルフードへ（Combo Feed Result → Special Food）
コンボが発動した場合：
- PAGE_FEED_RESULTに「COMBO」テキストが表示
- ANIM_COMBOが再生（約1000ms）
- コンボアニメーション終了後、スペシャルフード選択へ進む
```
btn l          # スペシャルフード一覧でカーソル移動
btn r          # スペシャルフード一覧でカーソル移動
btn m          # スペシャルフードを選択
                # 確認画面は最低 1 秒表示
                # その後待機に戻る
```

### 6. 麻婆豆腐の発動（Mapo Tofu Trigger）
スペシャルフード選択中に麻婆豆腐が発動した場合：
- ANIM_MAPO_TOFUが再生（約1500ms）
- アニメーション中は入力がブロック
- アニメーション終了後、待機に戻る

### 7. つつく（Poke）
```
btn r          # つつくアニメーション再生（約 500ms）
                # アニメーション完了後、待機に戻る
```

### 8. 破棄・3 キー同時押し（Destroy，3-key combo）
```
ctx            # 現在のコンテキストを確認
# 物理的にL+M+Rを同時に5秒押してリセット確認を試します。
# btnl lはLだけの長押しで、3キー同時押しにはなりません。
# resetは確認を省略し、ペットをリセット／オーナーを復元します。
```
破棄確認：デフォルトカーソルはNO（安全）。L/Rで移動、Mで確認。

### 9. オートセーブ（Auto-save）
自動保存は定期的にトリガーされます。画面下部に簡潔な「Autosaved」トーストを表示し、現在のページやアニメーションを中断しません。

## シリアルセーブ インポート/エクスポート

バックアップ・移行に加え、ペットのみの交換（ビジット）用途でもスロット単位のシリアル入出力に対応しています。

### デバイス状態・エクスポート種別・ビジットモード

スロット外に**デバイス固有**で保持される項目があります：**`rounds`**（フル／ビジットのインポート成功時に増加）、**`device_clock_epoch`**（**`SET_TIME`** と組み合わせたオフライン追いつきの基準）、ビジット用フラグ（ビジット中か、オーナースロット凍結、開始時刻）。シリアル **`devinfo`** で確認できます。

- **`SAVE_EXPORT <slot>`** — **フルバックアップ**：ペット＋図鑑バンドル（サイズ大）。
- **`SAVE_EXPORT_PET <slot>`** — **ペットのみ**：交換・**ビジット**用（サイズ小、図鑑ブロックなし）。
- **`SAVE_IMPORT_BEGIN`** 後に **`[SaveImport] READY ... target_bytes=... (legacy=...)`** が出ます。フルとペットのみの期待バイト数です。**`SAVE_IMPORT_COMMIT`** 前にファイル長がどちらかと一致している必要があります。

**フルインポート**（ペイロード長＝フル）：バンドルから図鑑を復元し、アクティブペアを再構成し、ペットのタイムスタンプをローカル時計に合わせ、ビジット状態を解除し、**`rounds`** を増やし、**`device_clock_epoch`** を更新して保存します。

**ペットのみインポート**（ペイロード長＝ペットのみ）：**ビジットモード** — アクティブ2スロットのうち新しい方を**オーナー**としてディスク上で凍結し、インポート先スロットに**ゲスト**を置いてRAMに読み込みます。ローカル図鑑は維持しつつ、ゲストの現在形態が必要なら解放します。インポート先がオーナーの最新スロットと同じ場合は **`REJECTED`** になります（もう一方のアクティブスロットを使ってください）。**`rounds`** と **`device_clock_epoch`** はフル時と同様に更新されます。

**ビジット中：** 新規インポートと **`stime`**、**`t <min>`**、**`d`** は拒否します。通常プレイ中の **`SET_TIME`** も拒否しますが、電源断後の設定待ちではゲストの時刻確認・補償が可能です。オーナーは凍結したままです。**`reset`** はゲストを破棄してオーナーを復元し、ビジットを終了します。不正パケット（例：**`save_time == 0`**）は **`[SaveImport] REJECTED:`** で中止します。

### ファームウェア側コマンド

- `SAVE_SLOT_STATUS`：全スロット（`slot0`、`slot1`、`slot2`）の状態を取得。
- `SAVE_EXPORT <slot>`：**フルバックアップ**（ペット＋図鑑）をhexブロックとして出力。
- `SAVE_EXPORT_PET <slot>`：**ペットのみ**スナップショットをhexブロックとして出力。
- `SAVE_IMPORT_BEGIN <slot>` -> `SAVE_IMPORT_DATA <hex>` -> `SAVE_IMPORT_COMMIT`：ペイロード長でフル復元かビジットかが決まります。
- `SAVE_IMPORT_ABORT`：現在のインポートセッションを中止。
- `s0` / `s1` / `s2`：スロット単位のスナップショット状態を表示。
- `devinfo`：デバイス状態（rounds、ビジット、クロックepoch）。

### ホスト側ヘルパー（Python スクリプト）

`SaveManager` ディレクトリで実行：

```bash
py save_manager.py
```

CLI直接実行：

```bash
py save_manager.py --port COM5 status

py save_manager.py --port COM5 export --slot 0 --out slot0_pet.bin --pet-only
py save_manager.py --port COM5 import --slot 1 --in slot0_full.bin
```

### インポート時の挙動（重要）

- **フルバックアップ：** インポート先スロットはアクティブペアに入ります。残り2スロットのうち**古い**方がもう一方のアクティブになります（sequence 優先、必要なら save_time；空スロットは古い扱い）。残り1スロットは**凍結**し、以後の自動／手動ローテーション対象外です。成功時 **`[SaveImport] Full backup restored ...`** が出ます。
- **ペットのみ（ビジット）：** オーナースロットを凍結しゲストをインポート先に配置；成功時 **`[SaveImport] Visit started ...`**。**`reset`** でビジット終了・オーナー復元。
- インポート完了時にデバイスが**初回**時刻設定待ちなら、デバイスクロックのアンカーがあればその待ちを抜ける場合があります。通常の起動フローは変わりません。上記インポート経路では「古いセーブ時刻から現在まで一括オフライン清算」は行いません。
- インポート、オーナー復元、時刻確認は永続復旧マーカーで保護します。途中失敗時は再起動後もゲーム操作と自動書き込みを停止し、完全成功の表示や自動削除はしません。通常のv9交互保存はキーごとの書き込みで、複数キーのトランザクションではありません。

## ページホールド（Page Hold Behavior）

表示システムは「ページホールド（page hold）」で、結果や確認画面が確実に見える時間を確保します。

- **餌やり結果（ノンコンボ）：** 1500ms ホールド、入力ブロック、その後自動的に待機へ戻る。
- **スペシャルフード確認（麻婆以外）：** 1000ms ホールド、入力ブロック、その後自動的に待機へ戻る。
- **麻婆豆腐：** アニメーション 1500ms 再生（アニメーション側で管理し、ページホールドではない）。
- **起動：** 1500ms後に待機または必要な時刻設定へ遷移。復旧ロック中は通常のゲームを開始しません。
- **日次締め：** アニメーション 1500ms 再生、入力ブロック。
- **進化：** アニメーション 2000ms 再生、入力ブロック。
- **破棄アニメーション：** アニメーション 2000ms 再生、入力ブロック。

ホールドまたはアニメーション中は `isPageBlockingInput()` が true を返し、MenuController は入力処理をスキップします。

## 検証と手動復旧

オフライン修復テストは周辺機器アダプターを使い、実際のセーブ・メニュー・時計・表示・シリアル処理を実行します。

```sh
python tests/host/run_all.py
```

元のベースライン履歴を保持するGitチェックアウトで実行してください。ABI検証に必要なESP32-S3コンパイラを用意するため、先にPlatformIOでビルドします。[修復報告](reports/original-repair/README.md)にコマンド、障害・中断テスト、制限を記録しています。この旧版修復ブランチはホスト回帰と2種類の表示ビルドを検証済みですが、物理ハードウェアは未検証です。エンジンの実機結果はこの版には適用されません。

v9形式は**ペットのみ72バイト／完全バックアップ84バイト**のままです。このファームウェアはエンジンのv10バックアップを読みません。通常のv9保存は複数NVSキーを使います。復旧マーカーはインポート、オーナー復元、時刻確認を保護し、すべての通常保存をトランザクション化するものではありません。

復旧時は、読めるスロットの完全バックアップを取り出してから明示的に消去します。スロット状態／デバイス状態を見て、実際に保持されているオーナースロットを選んでください。

```sh
python SaveManager/save_manager.py --port PORT export --slot 0 --out owner.bin
# バックアップを確認してから、シリアルでeraseを送信。ゲームのセーブを削除します。
```
