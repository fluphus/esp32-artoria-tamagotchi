# 👑 アルトリア・たまごっち (Fate/Grand Order バーチャルペット)

**ESP32-S3 (N16R8)** を搭載した、たまごっち風のバーチャルペットプロジェクトです。

あなただけのアルトリアを育てましょう！セイバー・リリィから旅を始め、彼女の成長を導きます。お世話やコミュニケーションに応じて、アーチャー、ランサー、ライダーなど、様々なクラスへと進化します。

## ✨ 機能
* **進化システム：** ペットのステータス（健康度、真面目さなど）に基づく複数の成長ルート。
* **時間・日付管理：** 日替わりのリセットや、食事を与えなかった場合のペナルティを処理する内部時計を内蔵。
* **永続ストレージ：** 3スロットセーブシステム。チェックサム検証、スロット単位のシリアル入出力、インポート後の時刻整合フローに対応。
* **インタラクティブなアクション：** 餌やり、つつく（Poke）、ステータス監視。
* **ディスプレイ：** TFT_eSPI経由のSSD1351 128x128 65K カラーOLED、ヘッドレステスト用のシリアルプレースホルダーバックエンド。

## 🚧 現在のプロジェクト状況

* ディスプレイ：TFT_eSPIバックエンド（SSD1351 128x128）とシリアルプレースホルダーバックエンドの両方がコンパイルおよび実行可能。
* 入力：3ボタン物理入力（L/M/R）、シリアルシミュレーション対応（`btn l|m|r`、`btnl l|m|r`、`btnr l|m|r`）。
* アセット：実際のスプライトが存在しない場合、プレースホルダー矩形とテキストを使用。

## 🛠️ ハードウェア要件

* ESP32-S3 開発ボード（N16R8 推奨）
* SSD1351 1.5" 128x128 65K カラーOLED（SPI）
* 3個のタクタイルボタン（GPIO 4、5、6）

## ビルド

```bash
pio run                    # ビルド（TFT_eSPIバックエンド、デフォルト）
pio run -t upload          # デバイスにアップロード
pio device monitor         # シリアルモニター（115200ボー）
```

シリアルプレースホルダーバックエンド（画面なし）に切り替えるには、`src/display/display_config.h`を編集してください：
```c
#define DISPLAY_BACKEND_SERIAL_PLACEHOLDER  1
#define DISPLAY_BACKEND_TFT_ESPI            0
```

## スモークテスト手順（シリアル/ボタン）

シリアルコマンドを使用してボタン押下をシミュレートします。115200ボーで接続してください。

### 1. ブート -> アイドル
電源を入れます。ブート画面は約1.5秒表示され、その後自動的にアイドル画面に遷移します。

### 2. ステータスパネル
```
btn m          # ステータスパネルを開く
btn m          # ステータスパネルを閉じる（アイドルに戻る）
```

### 3. 餌やりフロー
```
btn l          # 餌やりドロー開始（4枚の食物カードをアニメーション表示）
                # ドロー完了まで約800ms待機
                # 自動的に餌選択画面に進む
btn l          # カーソル左移動
btn r          # カーソル右移動
btn m          # カーソル位置の食物を選択（3つ選択するまで繰り返す）
btn m          # 2番目の選択
btn m          # 3番目の選択 -> 自動送信、餌やり結果を表示
                # 餌やり結果は最低1.5秒表示
                # その後自動的にアイドルに戻る
```

### 4. ノンコンボ餌やり結果保持
3つの食物を選択した後（コンボなし）：
- PAGE_FEED_RESULTは最低1500ms表示
- この保持期間中は入力がブロック
- 保持期間終了後、ページは自動的にアイドルに戻る

### 5. コンボ餌やり結果 -> 特殊食物
コンボがトリガーされた場合：
- PAGE_FEED_RESULTに「COMBO」テキストが表示
- ANIM_COMBOが再生（約1000ms）
- コンボアニメーション終了後、特殊食物選択に進む
```
btn l          # 特殊食物リストでカーソル移動
btn r          # 特殊食物リストでカーソル移動
btn m          # 特殊食物を選択
                # 確認画面は最低1秒表示
                # その後アイドルに戻る
```

### 6. 麻婆豆腐トリガー
特殊食物選択中に麻婆豆腐がトリガーされた場合：
- ANIM_MAPO_TOFUが再生（約1500ms）
- アニメーション中は入力がブロック
- アニメーション終了後アイドルに戻る

### 7. つつく
```
btn r          # つつくアニメーション再生（約500ms）
                # アニメーション完了後アイドルに戻る
```

### 8. 破棄（3キーコンボ）
```
btnl l         # L長押しをシミュレート（実際の操作では3キーを5秒押し続ける）
                # シリアルテストでは、'reset'コマンドを使用してください
                # または破棄確認UIをテスト：
ctx            # 現在のコンテキストを確認
```
破棄確認：デフォルトカーソルはNO（安全）。L/Rで移動、Mで確認。

### 9. 自動保存
自動保存は定期的にトリガーされます。画面下部に簡潔な「Autosaved」トーストを表示し、現在のページやアニメーションを中断しません。

### 10. デバッグコマンド
```

h              # ヘルプ
fl             # 食物リスト
t <min>        # N分進める

age <val>      # デバッグ: 年齢日数を設定

mapo           # デバッグ: 麻婆豆腐カウント +1
FORCE_NOBU     # デバッグ: nobuルートを強制
UNLOCK_ALL     # デバッグ: 全図鑑形態を解放
```

## シリアルセーブ インポート/エクスポート

バックアップおよび移行用途として、スロット単位のシリアル入出力に対応しています。

### ファームウェア側コマンド

- `SAVE_SLOT_STATUS`：全スロット（`slot0`、`slot1`、`slot2`）の状態を取得。
- `SAVE_EXPORT <slot>`：指定スロットをhexブロックとして出力。
- `SAVE_IMPORT_BEGIN <slot>` -> `SAVE_IMPORT_DATA <hex>` -> `SAVE_IMPORT_COMMIT`：指定スロットへインポート。
- `SAVE_IMPORT_ABORT`：現在のインポートセッションを中止。
- `s0` / `s1` / `s2`：スロット単位のスナップショット状態を表示。

### ホスト側ヘルパー（Python）

`SaveManager` ディレクトリで実行：

```bash
py save_manager.py
```

CLI直接実行：

```bash
py save_manager.py --port COM5 status
py save_manager.py --port COM5 export --slot 0 --out slot0.bin
py save_manager.py --port COM5 import --slot 1 --in slot0.bin
```

### インポート時の挙動（重要）

- インポート対象スロットは必ずアクティブセーブペアに含まれます。
- 残り2スロットから、より古い方がもう1つのアクティブスロットとして選択されます。
- もう1つのスロットは凍結され、以後の自動/手動上書きローテーション対象外になります。
- インポート後は時刻設定フローが強制され、オフライン補償は実行されません。
- 時刻確定後、インポート時刻を整合して保存します。検証失敗時は成功までバックグラウンド再試行を継続します。

## ページ保持動作

ディスプレイシステムは「ページ保持」メカニズムを使用して、結果/確認ページが表示されることを保証します：

- **餌やり結果（ノンコンボ）：** 1500ms保持、入力ブロック、その後自動的にアイドルに戻る。
- **特殊食物確認（非麻婆）：** 1000ms保持、入力ブロック、その後自動的にアイドルに戻る。
- **麻婆豆腐：** アニメーション1500ms再生（アニメーションシステムで管理、保持ではない）。
- **ブート：** 1500ms後自動的にアイドルに遷移。
- **日終了：** アニメーション1500ms再生、入力ブロック。
- **進化：** アニメーション2000ms再生、入力ブロック。
- **破棄アニメーション：** アニメーション2000ms再生、入力ブロック。

保持またはアニメーション中、`isPageBlockingInput()`はtrueを返し、MenuControllerは入力処理をスキップします。
